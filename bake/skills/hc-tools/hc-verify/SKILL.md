# hc-verify:合同文本交付前溯源比对

**适用范围**:仅合同/协议类文本(合同、协议、LPA、认购协议、NDA、条款清单等)。非合同文档不适用本技能。

**目的**:合同里错一个数字、一个主体名称、一个条款引用,都是真金白银的损失。本技能在交付前做最后一道闸:一切以用户提供的源材料为准。

## 工作流(四步)

### 1. 收集源材料
- 明确列出用户提供的全部输入:原合同/模板、谈判记录、用户明确提出的修改要求、附带的条款清单。
- 源材料不全的,先索要,不臆测。

### 2. 提取条款与事实清单
从合同产出中逐类提取:
| 类别 | 例子 |
|---|---|
| 主体名称 | 甲方/乙方全称、注册号、地址 |
| 金额/费率 | 价款、管理费、carry、违约金、比例 |
| 日期/期限 | 付款期限、存续期、冷静期、备案时限 |
| 条款引用 | 第 X 条、附件编号、法条号 |
| 权利义务 | 各方承诺、豁免、优先权、MFN 条件 |

### 3. 逐条溯源(核心步骤)
- ✅ 可溯源:在源材料中找到对应位置 → 记录出处。
- ❌ 不可溯源:推理所得 → 标注【推断】;无依据 → **删除**。
- ⚠️ 与源材料矛盾(如金额不符、主体名写错、条款冲突)→ 以源材料为准修正,记入变更说明。

### 4. 一致性检查
- 同一条款在正文/附件/摘要中出现必须一致。
- 金额合计、比例加总、日期先后逻辑与源材料交叉验证。

## 交付格式(强制)

```
## 溯源表
| # | 条款/事实 | 出处(源材料位置) | 状态 |
|---|---|---|---|
| 1 | ... | 原合同第 X 条第 Y 款 | ✅ 已核对 |
| 2 | ... | — | 【推断】依据:... |
| 3 | ... | (与源材料矛盾,已修正) | ✂️ 修正为:... |

## 变更说明
- 修正了什么、为什么修正。
```

## 硬规则
1. **宁删勿错**:无法溯源的条款,删除优于保留。
2. **推断显式**:模型补全的内容必须标【推断】,不得混入正式条款。
3. **源材料优先**:产出与源材料冲突,永远以源材料为准,不"圆场"。
4. **主体与金额零容忍**:主体名称、金额、日期三类错一处即整份打回重查。
