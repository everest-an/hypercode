# 修改 hypercode.json 的安全规程

配置文件里放着用户的模型 API key。**任何形式的"读出来→重新生成→写回去"都会毁掉它**，
也会抹掉用户的注释和排版。本文件规定唯一允许的做法。

## 目标文件

按引擎的读取顺序，用户配置位于（Windows 与 macOS 路径一致）：

```
Windows: %USERPROFILE%\.config\hypercode\
macOS / Linux: ~/.config/hypercode/
```

候选文件名（引擎按此顺序读取，**后面的覆盖前面的**）：

```
config.json → opencode.json → opencode.jsonc → hypercode.json → hypercode.jsonc
```

优先改**已经存在的那个**；都不存在时创建 `hypercode.json`。
若设置了 `OPENCODE_CONFIG_DIR`，以该目录为准。

## 铁律

1. **禁止 `JSON.parse` → `JSON.stringify` 整文件回写**。文件允许 `//` 注释和尾逗号，
   序列化会把注释全部抹掉，并可能因格式变化让用户以为配置被篡改。
2. **禁止重写 `provider` / `model` / `plugin` 等段落**。本次操作只碰 `mcp`。
3. **先备份**：写之前把原文件复制一份为 `<原文件名>.bak-<时间戳>`。
4. **只动一个键**：一次操作只新增／替换用户明确选择的那一个连接器。
5. **写完必须复验**：重新读取整个文件并解析，确认改动后的文件仍然合法、且新键可解码。

## 操作步骤

### 第 1 步：读取原文

用文件读取工具读取目标文件的**原始文本**。不要用会丢注释的解析器。

### 第 2 步：定位

- 文件里**已有** `"mcp"` 键 → 找到它的值对象，在其**闭合花括号前**插入新条目。
  若同名连接器已存在 → 只替换**该连接器的值对象**，其余字符不动。
- 文件里**没有** `"mcp"` 键 → 在根对象的最后一个键值对之后补一个
  `"mcp": { <新条目> }`，注意补逗号。

### 第 3 步：构造条目

条目内容逐字取自 `connectors.md`，把 `<PLACEHOLDER>` 换成用户提供的真实凭据。

### 第 4 步：写回并复验

用文本编辑工具写入（保留缩进风格），然后：

1. 重新读取整个文件 → 解析 → 确认仍然合法（允许注释和尾逗号）。
2. 确认 `mcp.<名称>` 存在，且 `type` 与预期一致。
3. 确认 `provider` / `model` / `plugin` 与改动前**逐字相同**（这是 API key 没被动过的证据）。
4. 告诉用户：需要**重启 HyperCode** 才会加载新的 MCP 服务器。

## 凭据的归属与边界

连接器凭据（Access Token / Refresh Token / Client Secret）代表**某一个具体的人**的账号权限。
它和模型 API key 不是一回事：模型 key 花的是额度，连接器凭据读的是这个人的私人邮件、日历和文档。
写入前必须确认三件事：

1. **只写进这份配置所属的全局目录**（见「目标文件」）。**不得**写进任何会被提交、同步或共享的
   位置：项目级 `.opencode/` / `.hypercode/` 配置、dotfiles 仓库、共享盘、`~/HyperCodeVault/`、
   聊天记录、issue 或 PR。
2. **写前确认该目录不在 git 仓库内**。在目标目录执行：

   ```sh
   git rev-parse --show-toplevel
   ```

   若它输出一个路径（而不是 `not a git repository`），说明该配置已被版本控制，凭据可能被提交。
   **先停下来告诉用户**，由用户决定是否继续，不要默默写入。
3. **不要复制到第二个人或第二个部署**。凭据属于一个人；把它交给别人，等于把那个人的
   邮箱、日历和网盘交出去。

若用户的部署形态是工作台（Web / 移动端共享同一个访问密钥的多端部署），
写入后必须明确告知：**任何能访问该实例的人都能使用这些连接器**，而不仅是凭据本人。

## 失败处理

- 复验不过 → 立刻用第 3 步的备份还原，并如实报告失败，不要留下半截配置。
- 用户在对话里贴了密钥 → 只写进配置文件，**不要在回复里回显密钥**，写完后提醒用户
  该密钥以明文存在于配置文件中，注意该目录的权限与备份。
- 凭据疑似已泄露（被提交、被同步到共享位置、误发给他人）→ 让用户立刻去发证方
  **撤销该授权并重新授权**。仅删除本地配置不够，旧 token 在撤销前依然有效。
