# 网关与模型接入设计

> 目标:默认算力走 trust3.pro,用户零配置;同时支持用户自带模型(BYOK);免费额度策略借鉴 Zen 教训。
> 前提事实:trust3.pro 按 OpenAI 兼容端点接入(baseURL 可插拔,具体路径上线前实测确认)。

---

## 1. OpenCode 免费额度的真相(回答"哪里来的")

调研结论:OpenCode 的免费额度来自 **Zen**(opencode.ai 自营推理网关),构成:

| 来源 | 机制 | 代价 |
|---|---|---|
| 供应商预览模型 | Big Pickle / MiMo Free / Hy3 Free / Nemotron Free 等——**厂商为收集反馈限时免费** | 随时断供,用户天天撞 "Free usage exceeded" |
| OpenRouter `:free` 变体 | 聚合平台的免费通道 | 同上,更不稳定 |
| 平台补贴 | anomalyco(VC 资金)按 IP 限流、动态额度 | 烧钱换增长,不是商业模型 |

**教训**:免费额度 = 供应商促销 + 平台补贴,**不是可持续打法**。Zen 用户的抱怨集中在"想付费都用不了"(免费模型不接余额)——体验极差。**我们的策略**:免费只做"一次性试用点数",用完引导订阅;不做"限时免费模型"钩子。

## 2. 模型接入三层架构

```
┌─ L1 用户层 ── HyperCode CLI(用户只看到:hc + 模型选择器)────────┐
│   默认:"HyperCode 模型"(无 key 感知)                           │
│   BYOK:/connect 或 hypercode.json 自定义 provider               │
└───────────────────────────────────────────────────────────────┘
┌─ L2 网关层 ── HyperCode Cloud(登录/计费/计量/路由)─────────────┐
│   用户登录 → 发短期凭证 → 请求转发上游 → 按点数计量扣费          │
│   裸 key 只存服务端,永不下发客户端                              │
└───────────────────────────────────────────────────────────────┘
┌─ L3 上游层 ── trust3.pro(默认)/ DeepSeek 官方 / 其他国产(可插拔)┐
│   OpenAI 兼容 baseURL,故障时自动切换备上游                      │
└───────────────────────────────────────────────────────────────┘
```

## 3. 默认算力:trust3.pro

| 项 | 设计 |
|---|---|
| 接入协议 | OpenAI 兼容(baseURL:`http(s)://trust3.pro/.../v1`,上线前实测确认) |
| 凭证流 | 登录 HyperCode Cloud → 网关注入短期凭证(env `HYPERCODE_API_KEY`)→ 客户端**不落盘裸 key** |
| 信任边界 | 上游裸 key 只存网关服务器;客户端持短期令牌,可吊销 |
| 模型映射 | trust3 的 DeepSeek V4 Pro/Flash 映射为 `hypercode-pro`/`hypercode-flash`(用户不感知上游模型名) |
| 故障转移 | trust3 不可用 → 网关自动切 DeepSeek 官方/备上游(用户无感) |

## 4. BYOK:用户配置自己的模型(原生能力,零开发)

opencode 原生支持任意 OpenAI 兼容 provider + TUI `/connect` 命令。配置形态:

```jsonc
// hypercode.json —— 用户自加:
{
  "provider": {
    "my-deepseek": {
      "npm": "@ai-sdk/openai-compatible",
      "options": { "baseURL": "https://api.deepseek.com/v1", "apiKey": "{env:DEEPSEEK_API_KEY}" }
    }
  }
}
```

- 自带 key 用户:**我们不计量、不抽成**,模型费用由用户与上游直接结算(与 opencode Zen "own keys" 一致)
- 产品价值:自带 key 用户仍享受我们的记忆/压缩/Omega/编排能力

## 5. 默认 provider 配置(安装器预写)

```jsonc
// bake/templates/hypercode.json —— 默认形态
{
  "plugin": ["oh-my-openagent"],
  "provider": {
    "hypercode": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "HyperCode",
      "options": {
        "baseURL": "http://trust3.pro/v1",        // 网关/上游地址,上线前实测
        "apiKey": "{env:HYPERCODE_API_KEY}"        // 登录时由网关注入环境变量,不落盘
      },
      "models": {
        "hypercode-pro":   { "name": "HyperCode Pro" },
        "hypercode-flash": { "name": "HyperCode Flash" }
      }
    }
  }
}
```

## 6. 免费额度策略(吸取 Zen 教训)

| 策略 | 做法 |
|---|---|
| 试用点数 | 注册送 ¥30 等值点数,一次性(够跑几小时自主任务) |
| 无"限时免费模型" | 不学 Zen 的烧钱钩子;免费=试用,不是常态 |
| 透明计量 | 点数消耗实时可见(Omega 面板 + `hc stats`) |
| 断点保护 | 点数耗尽前警告,耗尽后明确报错引导订阅(不静默降级) |
