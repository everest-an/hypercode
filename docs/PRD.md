## 1. 执行摘要

HyperCode 是一款**面向中国大陆开发者的自主软件工程师**:用户给一份 PRD,HyperCode 自动分解任务、并行开发、自动写测试、跑到绿、交付可运行代码——整个过程可持续数小时无人值守,崩溃不重来、上下文不退化、越用越懂你的项目。

产品体验上:下载一个安装器、微信登录、开箱即用,免 VPN、免配置 key、免折腾插件。底层基于开源核心深度定制(OpenCode 引擎 + oh-my-openagent 编排能力 + Graft 代码地图),上层自研五大智能服务(规划 / 代码地图 / 调度 / 记忆 / 验证)。主力模型 DeepSeek V4 Pro,调度兜底用国产模型。

**一句话定位**:大陆开发者的"把 PRD 交给它,睡一觉起来验收"。

## 2. 背景与问题

### 2.1 目标用户的核心痛点(按痛苦程度排序)

| # | 痛点 | 现状 |
|---|---|---|
| P1 | Claude Code 封号、限流、断供 | 大陆用户需外卡 + VPN,账号随时没;Anthropic 风控持续收紧 |
| P2 | 现有方案"不能连续自主干活" | 裸 OpenCode 无自动连续性;装插件后上下文变长会卡顿/卡死 |
| P3 | **"PRD → 可运行代码"仍靠人** | 现有工具短时自主都困难,长时自主几乎不存在,人还是核心瓶颈 |
| P4 | 折腾成本高 | 装插件、配 MCP、配模型、配代理,每一步都在劝退 |
| P5 | 黑盒不透明 | Agent 长时间运行时用户不知道它在干什么、做到哪了,不敢撒手 |
| P6 | 记忆不持久 | 每次会话从零开始,同样的坑反复踩,项目上下文反复重新解释 |

### 2.2 市场背景

- Cursor/Windsurf 教育了市场,但定价($20/月)对大陆开发者偏高,且需外卡支付。
- 国产 Trae、Qoder(原通义灵码)已转向订阅收费(¥49-699 / ¥59-169),且都在推"自主/云端任务"功能——**自主赛道在大陆已被大厂验证有付费意愿**;但它们无持久记忆、无长时自主、无可视化。
- **自主软件工程师赛道**(Devin、OpenHands/All-Hands)已验证需求,但:① 海外产品大陆用不了/贵;② 现有自主 agent 的"有效自主时长"普遍只有几十分钟到一两小时,且不稳定。
- DeepSeek 等国产模型成本仍显著低于海外,但 2026-08 已大幅涨价(V4 Pro 输出峰时 ¥27/百万 token,见 §11)——"月付几十元"仍有空间,但重度自主长跑必须按量计费。
- 开源生态成熟度:OpenCode(MIT)引擎稳定,oh-my-openagent(SUL-1.0)补齐编排,Graft(MIT)补齐代码地图——定制起点极高。

## 3. 市场与竞品

| 竞品 | 模式 | 弱点(我们的机会) |
|---|---|---|
| Cursor / Windsurf | 海外订阅 $20/月 | 外卡门槛、VPN、无长时自主、记忆弱 |
| Claude Code(直连) | 订阅 | 封号限流断供风险,大陆不可直接购买 |
| Trae / 通义灵码 | 免费 IDE 插件 | 无自主长跑、无持久记忆、无可视化 |
| **Devin / OpenHands(自主 agent)** | 云端自主开发 | 大陆不可用/贵;有效自主时长短;不透明 |
| 各种"套壳站"(如 ohmyopencode.com) | 收钱卖安装器 | 假冒、不可信、无自研价值层;官方已警告 |
| 裸 OpenCode + 插件 | 免费开源 | 配置折腾、长上下文卡顿、无计费无服务 |

**差异化结论**:不拼"能写代码"(同质化),也不纯拼"自主"(Devin 已有),拼的是**"买得起 + 零折腾 + 有效自主时长 + 看得见"**四者的交集——这是大陆市场目前没人做好的。

## 4. 产品定位与价值主张

- **一句话**:买得起、不用折腾、能把 PRD 变成可交付代码的自主软件工程师。
- **核心承诺(分级,诚实表述)**:
  - MVP 承诺:**单任务自主 30 分钟**(写一个功能、修一批 bug、跑绿一个模块)。
  - V2 目标:**单 PRD 自主 2-4 小时**(分解+并行+验证,中途可自动续)。
  - 远期愿景:**跨夜交付**(睡一觉起来验收),但作为愿景而非承诺。
- **对个人开发者**:每月几十元,替代 Claude Code,不封号不限流不折腾。
- **对小团队(后续)**:共享记忆库 + 审计,团队版收费理由。
- **反定位**:明确不是"又一个套壳站"。价值在五大自研智能服务层,壳只是地基。

### 4.1 诚实预期(⚠️ 决定口碑的边界)

"好几个小时完全自动 + 自动测试交付"是**当前技术的前沿上限**,不是标配。行业里 Devin、Cursor、OpenHands 都只能做到"短时自主 + 人类中途介入"。**决定"能自主多久"的不是模型多聪明,而是三件工程**:

1. **检查点恢复**——崩了从快照续做,不重头再来;
2. **上下文压缩**——长跑不退化、UI 不冻结;
3. **验证环**——写出来的东西真能跑、测试真能绿。

这三件恰好就是 HyperCode 的核心护城河(§8 智能体系)。产品叙事要克制:从"单任务 30 分钟"起步,逐步拉到小时级,切忌一上来吹"全自动交付",否则口碑反噬。

## 6. 总体架构

### 6.1 产品六层架构

```
① 分发层  HyperCode Installer(Windows 优先 → macOS)
          · 一键安装,静默装运行时,内置国内镜像,全程免 VPN
          · 微信/手机号登录激活,设备授权,自动更新,损坏自愈
② 引擎层  HyperCode CLI(基于开源核心深度定制,详见 §8.2 改名清单)
          · 编排能力 + 代码地图编译期内置,用户零配置
③ 智能层  ★核心护城河★ 五大本地守护进程(独立服务,不耦合引擎插件 API)
          · hypercode-planner   规划器(PRD → 任务树)
          · hypercode-codemap   代码地图(fork Graft,代码结构理解)
          · hypercode-scheduler 调度器(并行子代理执行 + 断点续做)
          · hypercode-memory    记忆服务(awareness 模式,自研)
          · hypercode-verifier  验证环(测试→定位→修复→重跑)
          · hypercode-compactor 压缩服务(长跑不崩不退化)
          · hypercode-router    调度路由器(多模型故障转移)
          · hypercode-context   上下文编排器(协调各层注入,防上下文爆仓)
④ 可视化层 本地 Vault + 内置 Viewer
          · Agent 实时写:任务树 / 决策日志 / 进度 / 遗留问题
          · 兼容 Obsidian 直接打开
⑤ 网关层  HyperCode Cloud(大陆服务器,多线 BGP)
          · API 代理(裸 key 永不下发)、用量计量、许可证、计费
⑥ 计费层  订阅制 + 点数制
```

### 6.2 智能层内部(自主开发闭环)

```
PRD 进来
  ↓
[① 规划器] PRD → 任务树分解(依赖排序、可并行度分析、验收标准抽取)
  ↓
[② 代码地图] 一次性构建代码结构图(模块/符号/调用链),全程复用,子代理不迷路
  ↓
[③ 调度器]   并行子代理执行(写代码 / 写测试 / 修 bug 分工)
  ↓ ← 检查点(checkpoint)+ 后台压缩,支撑数小时不崩
[④ 记忆]     决策/踩坑/偏好跨会话累积,越用越强
  ↓
[⑤ 验证环]   跑测试 → 失败 → 定位 → 修复 → 重跑,直到绿 → 交付
  ↓
[⑧ 上下文编排器] 全程按任务阶段决定注入"代码图节点"还是"经验记忆",防爆仓
```

**关键架构原则**:
1. ③ 所有智能服务从第一天起就是**独立本地服务**(HTTP/gRPC 守护进程),通过标准接口与引擎交互,**不深度耦合上游插件 API**——上游大版本更新不会炸掉我们,未来换引擎核心甚至自研都平滑。
2. 用户代码与 prompt 处理以本地为主;云端只做网关/计量/账号,**代码不上传**(隐私即卖点)。

## 8. 核心功能规格

### 8.1 一键安装器(HyperCode Installer)

| 项 | 规格 |
|---|---|
| 平台 | Windows 10/11 x64 优先 |
| 流程 | 下载 exe → 双击 → 微信扫码登录 → 自动装运行时 + CLI + 服务 → 弹出终端可用,全程 ≤ 3 分钟 |
| 免 VPN | 所有依赖(运行时、模型 API)走国内镜像/CDN |
| 运行时 | 内置所需运行时,不要求用户装任何东西 |
| 升级 | 后台检查 + 灰度推送;升级失败自动回滚 |
| 自愈 | 诊断命令 `hc doctor`:一键检测并修复常见故障 |
| 卸载 | 干净卸载,明确告知删除范围 |

**验收标准**:小白开发者从下载到跑通第一个任务 ≤ 3 分钟;安装成功率 ≥ 98%。

### 8.2 HyperCode CLI(引擎层)

**技术路线(Phase 2 技术验证时最终拍板,三个候选)**:

| 方案 | 说明 | 评估 |
|---|---|---|
| A. Fork OpenCode + 内置 Ultimate 版插件 | 直接 fork opencode 仓库,把 oh-my-openagent 能力作为内置模块编译进去 | 改动量大,但最可控 |
| B. Fork Senpi 独立版(omo-ai) | 官方"无需宿主、单命令"的独立版,起点更接近一键式愿景 | 需评估成熟度(当前 beta) |
| C. OpenCode 引擎 + 我们自己的编排层 | 引擎只保留最稳的部分,编排能力自研(工作量大,但护城河最深) | 中长期目标 |

**改名清单(硬性要求,用户不可见上游痕迹)**:

| 维度 | 现状 | 改为 |
|---|---|---|
| 二进制/命令 | `opencode` | `hypercode`(别名 `hc`) |
| 配置目录 | `~/.opencode` | `~/.hypercode` |
| 环境变量 | `OPENCODE_*` | `HYPERCODE_*` |
| 配置文件 | `opencode.json` | `hypercode.json` |
| 日志/错误文案 | 出现 opencode 字样 | 全部 HyperCode |
| 启动横幅/帮助 | 上游品牌 | HyperCode 品牌 + 版本号 |
| 子代理命名 | oracle/momus/prometheus 等 | 中性或中文友好命名(如 架构师/评审员) |
| 关于页 | — | 保留开源致谢(法律要求,见 §10.2) |

**内置能力(用户零配置)**:
- 自动连续性(子代理编排、断点续做)
- 预配置 MCP(全部走国内可达端点;代码地图层用 fork 后的 CodeMap 替代上游 codegraph)
- 预配置模型:DeepSeek 主力 + 调度路由(见 8.7)
- 遥测:**强制关闭上游遥测**(PostHog、Graft 用量 ping、npm 版本检查等),用户数据绝不上传上游

### 8.3 代码地图(hypercode-codemap,fork Graft)

**定位**:自主开发闭环的"地图"——让 Agent 每次开工**不再从头摸索代码**,子代理拿到的是"这个模块是干嘛的、谁依赖它",而不是冷启动去 grep。

**为何 fork 而不是用原版**:原版 `npx @nanonets/graft` 会把品牌、遥测、npm 版本检查带进用户环境,违背"无感 + 大陆可达"目标。fork 后改名 + 关遥测 + 预构建,才能做到零痕迹。

| 项 | 规格 |
|---|---|
| 上游 | NanoNets/Graft(MIT,3.9k stars) |
| 机制 | 两层构建:① tree-sitter 结构图(纯本地、零成本、不用模型、~3ms 刷新);② LLM 总结文件成"概念节点"(markdown,用 DeepSeek 生成) |
| 存储 | 项目内 `hypercode-map/` 目录(链接式 markdown 节点,gitignore,可再生缓存) |
| 构建时机 | 项目首次打开自动构建;每次编辑后后台增量自同步(结构层 $0) |
| 注入 | 任务开始注入相关节点 + 编辑文件时提示"影响面"(blast radius) |
| 供应商 | `GRAFT_BASE_URL` 走 DeepSeek 的 OpenAI 兼容端点 |
| 遥测 | 强制关闭(DO_NOT_TRACK=1 + 从源码构建) |

**实测收益(上游基准,供定价与宣传引用)**:token -42%、工具调用 -46%、耗时 -60%、SWE-bench 正确率 54%→66%(+12 分)。

**验收标准**:同一项目第二次任务,Agent 不再重复探索代码;编辑文件时能在 1 秒内给出影响面提示。

### 8.4 规划器(hypercode-planner)

| 项 | 规格 |
|---|---|
| 输入 | 用户 PRD / 一句话需求 / 现有 issue |
| 输出 | 任务树(依赖排序 + 可并行度标注 + 每任务验收标准) |
| 分解策略 | 按模块/文件边界切分;识别可并行的独立子任务 |
| 验收标准抽取 | 每个子任务生成"什么算完成"(测试点/行为描述) |
| 人工介入点 | 分解完成后可预览任务树,用户可增删改再放行(默认自动放行) |

### 8.5 调度器(hypercode-scheduler)

| 项 | 规格 |
|---|---|
| 并行执行 | 独立子任务并行派发给子代理(写码/写测/修 bug 分工) |
| 断点续做 | 崩溃/断电从最近 checkpoint 恢复,已完成的子任务不重做 |
| 资源控制 | 并发度上限、每子任务 token 预算 |
| 进度上报 | 实时写 Vault(§8.8),用户随时可见 |

### 8.6 验证环(hypercode-verifier)

| 项 | 规格 |
|---|---|
| 流程 | 跑测试 → 失败 → 定位失败原因 → 修复 → 重跑,循环直至绿或达到上限 |
| 上限 | 每子任务最多 N 轮修复(防死循环),超限标记为"需人工" |
| 交付标准 | 测试绿 + 无新增 lint 错误 + 行为符合验收标准 |
| 证据 | 交付时附测试通过记录(用户可复现) |

### 8.7 调度路由器(hypercode-router)

| 项 | 规格 |
|---|---|
| 模型池 | 主力 deepseek-v4-pro;轻量任务 deepseek-v4-flash(成本 1/3);规划/难点 deepseek-r1;兜底 qwen-max / kimi / glm |
| 路由规则 | 默认主力;任务复杂度评估(多步/跨文件/架构级)→ 升级;连续失败 2 次 → 换模型重试 |
| 故障转移 | 模型挂掉/限流 → 秒级切换备用,对用户无感;全池不可用 → 明确报错并排队重试 |
| **错峰调度** | **非紧急自主任务自动排 DeepSeek 谷时(9-12/14-18 之外,价格减半);紧急任务即时执行** |
| 成本护栏 | 每会话/每日预算上限,可配置 |
| 自带 key | 高级用户可接 Claude/GPT(用户自担合规,产品方免责声明) |
| 计费联动 | 不同模型不同点数权重(主力最便宜) |

### 8.8 记忆服务(hypercode-memory)

借鉴 awareness.market / claude-mem 模式,**自研实现**(不依赖其云——大陆延迟与数据出境合规都不允许)。

| 项 | 规格 |
|---|---|
| 存储 | 本地 SQLite:`~/.hypercode/memory.db` |
| 数据模型 | observation(id, ts, project, session, type, content, tags, embedding, importance) |
| type 枚举 | decision(决策)、learning(经验)、error(踩坑)、pattern(代码模式)、preference(偏好) |
| 写入时机 | 每个任务/子任务结束自动写入;错误恢复后自动记录根因 |
| 检索 | 任务开始前:项目过滤 + 语义检索 top-k,注入系统提示("关于这个项目,你记得:...") |
| 用户命令 | `/remember`(主动记)、`/recall`(查)、`/forget`(删) |
| 记忆强度 | 引用次数加权;长期未引用的记忆降权沉睡(类似遗忘曲线) |
| 团队版 | 记忆库加密同步云端,按团队共享(权限:只读/读写) |

### 8.9 压缩服务(hypercode-compactor)——解决长上下文卡死

**根因分析**(用户报告"上下文长了会卡住"):上下文全驻内存 + 压缩在主线程做 + 摘要时阻塞 UI。

| 项 | 规格 |
|---|---|
| Checkpoint | 会话状态每 N 轮 / 每 M token 落盘快照,内存只保留活跃窗口 |
| 后台压缩 | 独立进程渐进式摘要,**永不阻塞主循环**;主进程 P95 响应 < 100ms |
| 摘要链 | 分层:每 10 轮小结 → 每 50 轮中结 → 全局摘要;任意层级可回溯 |
| 不丢信息 | 压缩时关键信息(决策、约束、坑)先写入记忆服务再丢弃 |
| 窗口策略 | 滑动窗口(最近 ~20k token)+ 摘要链 + 记忆检索回填 |
| 智能触发 | token 逼近阈值时预压缩,而不是满了才卡;预测性触发 |
| 断点续做 | 崩溃/断电后从最近 checkpoint 恢复,不重头开始 |

**验收标准**:8 小时长任务运行,内存占用稳定、UI 不冻结;压缩后任务完成率不下降(基准任务集测)。

### 8.10 上下文编排器(hypercode-context)
