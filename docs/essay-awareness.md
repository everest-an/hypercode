# 参赛手记 | 我们让 AI 连续干活几个小时,然后它自己交了活

> 第三届 NVIDIA DGX Spark Hackathon · 团队 awareness · 项目 HyperCode

## 一、起因:AI 都会聊天,但不会"干活"

先说一个我们深有同感的场景:你给 AI 一段完整的工作,它回你一段看起来很像样的回答;但你把它当成"能交活的同事"来用,问题立刻暴露——

- 干着干着**上下文炸了**,跑到一半就"失忆";
- 跑着跑着**跑偏了**,在无关细节里打转;
- 错了**自己不会修**,最后擦屁股的还是人;
- 想交给它一个"干几小时"的长任务,几乎没有工具接得住。

所以我们组了队(**awareness**),做了一个反方向的东西:**不做聊天机器人,做一个能自己把活干完、并把成果交付回来的自治工作系统 —— HyperCode。**

这次参加 **第三届 NVIDIA DGX Spark Hackathon**,主题是 **Agent Skills 与自主工作**,和我们一直在做的事高度重合,于是把最近的工程成果整理成参赛作品。

## 二、我们把"长任务"当第一性问题

做了一段时间我们才想明白:**能不能自主干活,拼的不是模型多聪明,而是工程。**

一个 Agent 想连续工作几个小时不崩不跑偏,至少要三件东西:

1. **检查点**:干一段就存档,崩了、断电了,从断点续跑,而不是从头再来;
2. **上下文压缩**:长任务不炸内存、不丢关键信息,把决策/约束/踩过的坑先沉淀下来;
3. **验证环**:干完自己验证 —— 跑测试、失败、定位、修复、重跑,直到绿了才交付。

**别人靠状态,我们靠制度。状态会掉,制度不会。** 这也是我们把"有效自主时长"当成北极星指标的原因。

## 三、这次黑客松我们补上的一块:网页操作

除了长任务,这次我们重点打磨了 **Agent 驾驶真实浏览器** 的能力(网页操作工作台):

- Agent 直接操作真实网页 —— 浏览、检索、读邮件、处理附件;
- **动作全程可见**:每一次点击/输入/读取都流式呈现,进度、计划、审批一目了然;
- **随时接管**:需要时一键接管同一个浏览器会话,人机同屏接力;
- **护栏与授权**:浏览器侧做 SSRF 护栏兜底;真实的 Google 授权打通,授权完成后自动交接回工作台,不用人再手动刷新。

这块不是纸上功能 —— 我们把 web 工作台以 subtree 收编进主仓,补上了 4 组真实运行必需的修复(浏览器护栏与代理共存、工具结果回填、授权交接、取消路径),并做到 **234/234 测试通过、根仓全包 typecheck 全绿**,真机跑通真实授权全流程。

## 四、内置 Agent Skills:关键词无感触发

比赛主题是 Agent Skills,这恰好是我们投入最重的地方:**内置 229 项专业技能**,覆盖金融投研、法律实务、学术科研、私募基金四大域。

它的用法是"无感"的:你说"帮我做一份估值",它就走 DCF 工作流;说"审这份合同",它就调合同审查流程。**无需记命令,中英文说到相关需求即自动匹配工作流。** 对开发者,它写代码、跑测试、修 bug;对不写代码的人,它做估值、审合同、润色论文。

## 五、收获

十天里我们最大的体会是:**自主不是一句口号,是一连串很具体的工程取舍。** 什么时候压缩、什么时候落检查点、失败几轮转人工、上下文怎么编排不爆仓——每一个细节都决定"能自主多久"。

也正因为如此,我们不敢把话说满:我们说的是"从能自主 30 分钟,到小时级",而不是一上来就宣称"全自动交付"。**克制地承诺、扎实地交付**,才有口碑。
