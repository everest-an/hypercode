# 事故复盘:安装器撞车误删 OpenCode(2026-08-23)

> 级别:P1(用户数据破坏) · 状态:已修复 + 已加防回归措施

## 根因链

1. **早期构建缺少 `extraMetadata.name`**:electron-builder 用包名 `@opencode-ai/desktop` 生成安装目录 → HyperCode 与上游 OpenCode Desktop **撞进同一个目录** `%LOCALAPPDATA%\Programs\@opencode-aidesktop`
2. 该目录里同时存在两套 exe 和**共享的 `resources/app.asar`**
3. 升级安装时,新版安装器(相同 appId GUID)检测到旧安装 → **自动运行旧版卸载器**
4. 旧卸载器按 NSIS 默认行为**清空自己所在目录** → OpenCode 的 app.asar 等文件被连带删除 → 用户 OpenCode 损坏

## 已修复(客户无风险)

| 措施 | 提交 | 状态 |
|---|---|---|
| `extraMetadata.name = "hypercode-desktop"` | 28709277e | ⚠️ **不充分**:electron-builder 26.15.2 的 NSIS 安装目录取自原始 package.json name,v0.1.5 实测仍装进 `@opencode-aidesktop`;真正修复是改 package.json 的 name(2026-08-24,随 v0.1.6) |
| v0.1.4 为首个公开发行版 | — | ✅ 无客户持有撞车版安装 |
| 本地地雷清理(共享目录中我们的文件 + 注册表项) | — | ✅ 2026-08-23 完成 |

## 防回归承诺(写入发布检查清单)

1. **安装目录必须专属**:任何版本不得安装到与第三方产品共享的目录;`packages/desktop/package.json` 的 name 必须为 `hypercode-desktop`(测试断言原始 name 与 extraMetadata 一致)
2. **卸载测试必做**:每次发版前,在干净虚拟机验证:① 安装目录专属;② 卸载只清理自己的目录;③ 同机共存 OpenCode/其他工具零影响
3. **升级路径测试**:旧版 → 新版升级,确认旧卸载器只作用于自己的目录
4. **禁止共享目录**:任何 HyperCode 产物(配置/技能/插件/缓存)不得写入 `~/.omo/`(omo 共享配置,2026-08-23 另一事故)与第三方安装目录

## 教训

- 改名的正确顺序是**先隔离目录,再谈品牌**——品牌是面子,隔离是命
- 安装/卸载操作属于高风险动作,需人工确认,自动化脚本不自动执行
